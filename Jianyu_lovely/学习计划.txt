  2. RAG 核心流程（最重要）
     跟着代码走一遍完整的知识库问答流程：
     上传文档 → 文本切割 → Embedding 向量化 → 存入向量数据库
     → 用户提问 → 问题向量化 → 相似度检索 → 拼接 Prompt → LLM 生成回答
     重点文件：
       server/knowledge_base/      （知识库管理）
       server/chat/kb_chat.py      （知识库对话入口）
       server/file_rag/            （文件 RAG）

  3. Agent 流程
     - 什么是 Tool、什么是 AgentExecutor
     - server/agent/tools_factory/ 下有哪些工具，每个工具怎么写的
     - Agent 是如何决定"用哪个工具"的

  4. LLM 接入层
     - 项目如何兼容 OpenAI 格式 API
     - settings.py 里模型配置是怎么组织的

第二阶段：跑通项目，动手实验（1周）
==================================================

目标：
  在本地把项目跑起来，通过实际操作加深对代码的理解。

学习内容：
  1. 按照 README 完成环境配置和启动
  2. 用 Postman 或直接调用 FastAPI 的 /docs 接口，
     手动触发一次完整的知识库问答，观察日志
  3. 在代码里加几行 print，观察关键变量的值：
     - 检索到的文档片段（source_documents）长什么样
     - 最终拼给 LLM 的 Prompt 是什么内容
  4. 故意上传一个"很难检索"的文档，观察回答质量变化，
     思考为什么会这样

阶段产出：
  记录一篇实验日志，写下你发现的问题和疑问（这些将成为第三阶段的改进点）

第三阶段：选定方向，实现改进（3~4周）
==================================================

目标：
  选择一个具体方向深入改进，有可量化的效果对比，
  能清楚地描述"我发现了什么问题 → 我怎么解决的 → 效果如何"。

推荐改进方向（选其一即可，不要贪多）：

  【方向A】RAG 引用溯源（推荐新手首选）
    现状：回答时不显示来源，用户无法验证
    改进：在每条回答后附上来源文档名 + 原文片段 + 页码
    技术点：解析 source_documents，修改回答格式和 WebUI 展示
    简历亮点：提升产品可信度，可视化 RAG 过程

  【方向B】混合检索优化
    现状：只用向量相似度检索，对关键词精确匹配效果差
    改进：加入 BM25 关键词检索，与向量检索结果融合（RRF 算法）
    技术点：BM25（rank_bm25 库）、倒数排名融合
    简历亮点：提升检索召回率，有明确的技术方案

  【方向C】对话记忆优化
    现状：多轮对话历史直接堆叠，超长后截断丢失信息
    改进：实现"滚动摘要记忆"，对历史对话自动压缩摘要
    技术点：LangChain ConversationSummaryMemory
    简历亮点：改善用户长对话体验

学习方法：
  - 先读懂要改的那部分代码，再动手
  - 每次改动前 git commit 一次，方便对比
  - 改完后和原版对比效果，记录数据

阶段产出：
  完整的代码改动 + 一份《改进说明文档》（写给面试官看的）
